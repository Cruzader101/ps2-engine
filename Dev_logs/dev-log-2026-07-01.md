- Wrote my first `src/main.cpp` (`int main() { return 0; }`), built `ps2-engine.exe`,
  ran it → **exit code 0**. Toolchain proven end to end.

## What I broke & how I figured it out

- **Bug 1 — `set(CMAKE_CXX_STANDARD C++17)`:** the variable wants the bare number `17`,
  not the string `C++17`. CMake *composes* the compiler flag (`/std:c++17`) from the
  number, so the string is invalid. Fixed → `17`.
- **Bug 2 — first configure died at the GENERATE step:** `Cannot find source file:
  src/main.cpp`. I'd been told configure wouldn't care whether the file existed — wrong.
  **Corrected model:** CMake requires every listed source to *exist* at generate time,
  but only *reads/compiles its contents* at build time. Proved it: once the file existed,
  `Generating done` passed and the compile showed up in the build step (`[1/2] Building
  ...main.cpp.obj`) — a clean side-by-side of the phase boundary.
- Meta: I had assumed the phase behavior from memory and got it wrong → added a
  **"verify before you assert"** guardrail to my project notes. Run the experiment,
  don't trust recall.

## What I learned

- **CMake phases:** configure → generate → build. Existence checked at *generate*;
  contents compiled at *build*.
- **vcpkg manifest mode:** `vcpkg.json` + the toolchain file → `find_package(SDL2 CONFIG
  REQUIRED)` just works. It creates **imported targets** (`SDL2::SDL2`, `SDL2::SDL2main`)
  that carry SDL2's include dirs + libs, so linking one pulls its headers along — no
  manual `include_directories`.
- The `::` in a target name makes CMake **fail loud** on a missing/typo'd target instead
  of silently passing a bogus library name to the linker.
- `return 0` from `main` = exit code `0` = success (verified by running the exe).
- Set up narrate-back to run as a `/grill-me`-style interview; broadened `/grill-me` to
  cover grilling me on code I wrote. Candidate note: [[cmake-configure-vs-build]].

- **C++ seed — 3 tiny exercises, all done inside real `scratch_1.cpp`, verified by
  compiling + running** (no hypotheticals):
  1. **Function pointers** — `int (*addPtr)(int,int) = &add;` then called it. Fixed a

  2. **`__FILE__` / `__LINE__` — function vs macro.** Built `report()` (function) and
     `REPORT()` (macro), called each from two lines. Function printed its *own* line
     both times; macro printed each *call site*. Proved a function can't capture the
     caller's line.
  3. **`do { } while(0)`** — made a naive two-statement `CHECK` macro break a braceless
     `if`/`else` (`error C2181: illegal else without matching if`), then understood the
     fix.

## What broke & how I figured it out

- **Stale binary:** the macro version "printed the same as before" — I was running the
  old `.exe` without recompiling. Lesson: *the source on disk isn't what runs; the last
  compiled binary is.* (That's why we chain `cl ... && scratch.exe`.)
- **Unsaved buffer:** thought I'd added `CHECK` but the file on disk was unchanged —
  editor buffer ≠ saved file. Same class of trap, one layer up.
- **`C2181`:** a multi-statement macro pasted into a braceless `if` severs the `else`
  from its `if`. Bare braces `{}` don't fix it (the caller's trailing `;` becomes a
  stray empty statement). `do { ... } while(0)` does, because it's a single statement
  that *requires* the caller's `;` to complete → exactly one statement between `if`/`else`.

## What I learned

- A **function** freezes `__LINE__` at its definition (compiled once); a **macro** pastes
  its body to the call site first, so `__LINE__` expands against the caller's line. →
  `PS2_ASSERT` **must** be a macro to report where the bug actually fired.
- The `do { } while(0)` idiom = wrap a multi-statement macro body into one statement that
  eats the caller's semicolon.
- Candidate notes: [[gl-function-loading]], [[event-loop-double-buffering]],
  [[macro-vs-function-source-location]], [[do-while-zero-idiom]].
